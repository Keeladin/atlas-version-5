# Lessons Carried Forward from Atlas V3/V4

Atlas V5 is not a repudiation of earlier versions. V3 and V4 established useful technical truths and exposed architectural limits that should not be forgotten.

## Keep or preserve as concepts

- provider neutrality and replaceable models;
- local credential custody and authenticated service identity;
- MCP discovery and invocation experience;
- Google Workspace integration lessons;
- restart continuity and durable local state where continuity is actually needed;
- effect evidence and deterministic verification for consequential actions;
- observable provider/tool failures rather than confident fabrication;
- useful Control concepts for providers, tools, credentials, policy, usage, and diagnostics;
- Chat as the main conversational surface;
- clear separation between technical capability and actual authority.

## Reshape substantially

Memory should move from eager conversational capture into contextual memory plus asynchronous long-term processing.

Durable objective state should exist when a task genuinely needs continuity, but ordinary conversation must not be forced into Work objects.

Schedules remain useful, but as passive automation machinery rather than a major interaction model.

Capability inventory remains useful, but as the agent's situated capability map rather than a runtime planner's menu.

Control remains useful, but primarily as configuration, observability, and engineering diagnosis rather than routine operation.

## Do not carry forward as governing architecture

The V4 obligation-led execution path, runtime-driven planner rounds, mandatory capability-step decomposition, Work/Sources/Cadence as central user-facing abstractions, and source enrollment model should not constrain V5.

They may remain historically useful code in V4, but V5 starts from the new product model rather than migrating their semantics by default.
